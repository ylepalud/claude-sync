- [x] 3.1 Write failing tests in `tests/test_check_denylist.py` that run `scripts/check-denylist` with `subprocess` inside a temporary git repo (`git init` in `tmp_path`, local `user.name`/`user.email` set, `HOME` pointed at `tmp_path`): empty `DENYLIST` exits non-zero with `denylist is empty or missing`; comments and blank lines ignored; a term in `README.md` line 3 gives `README.md:3: term #2` and the output does not contain the term; a term in a file path is reported; a term added then removed is found by `--history` with the commit short sha (`<sha>:path #k:<line>`); a term in a commit message gives `<sha>: message`; `--staged` reports a staged added line as `<path>:<line>` with the line number from the hunk header; `--message-file` gives `message`, `--text pr-body` gives `pr-body`; matching is case-insensitive; a binary file is skipped; a clean repo exits 0. Exit codes: 3 for an empty or missing denylist, 1 for findings, non-zero refusal when a tracked file is named `denylist.txt`.
