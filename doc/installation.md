# Installation

## Requirements

| Requirement | Needed for |
| ----------- | ---------- |
| macOS | `init`, `uninstall` and `adopt` (they run `pgrep` and `launchctl`), `keychain:` references (the `security` tool) |
| zsh | The shell integration; `shell-init` only knows `zsh` |
| Python 3.11 or later | Everything; the package uses the standard library only |
| [uv](https://docs.astral.sh/uv/getting-started/installation/) | Installing the tool (`uv tool install`) |
| git | `profile create` (it runs `git init`), skill sources (clone, fetch, checkout), reading marketplace commits |
| The `claude` CLI | `import`, `status`, `apply` and `init`, which run `claude plugin ...` and `claude mcp ...` |

The package has no runtime dependency. The commands that only read or
edit the configuration (`which`, `list`, `config`, `map`, `unmap`,
`set-default`, `shell-init`) need neither `claude` nor git; the test suite
runs on Linux in CI. The migration is written for macOS.

## Install with uv

```sh
uv tool install git+https://github.com/ylepalud/claude-sync
claude-sync --version
```

`uv tool install` puts `claude-sync` in uv's tool directory (usually
`~/.local/bin`); make sure that directory is on your `PATH`
(`uv tool update-shell` adds it).

## Install from a clone with install.sh

```sh
git clone https://github.com/ylepalud/claude-sync
cd claude-sync
CLAUDE_SYNC_SOURCE=. ./install.sh
```

`install.sh` checks that `uv` is on `PATH` (and exits 1 with a link to
the uv installation guide when it is not), runs
`uv tool install --force --reinstall "$CLAUDE_SYNC_SOURCE"`, then prints
`claude-sync --version`. `CLAUDE_SYNC_SOURCE` defaults to
`git+https://github.com/ylepalud/claude-sync`, so `./install.sh` alone
installs from GitHub, and `CLAUDE_SYNC_SOURCE=.` installs the clone you
are in.

You can also run the tool from a clone without installing it:

```sh
uv run claude-sync --version
uv run python -m claude_sync --version
```

## Check the installation

```sh
claude-sync --version        # claude-sync <version>
claude-sync version --json   # {"version": "...", "python": "..."}
claude-sync help --all       # every command's help
```

## After installing

- Already using Claude Code: read [Migration](migration.md), then run
  `claude-sync init --dry-run` and `claude-sync init`. `init` adds the
  shell block to `~/.zshrc` for you.
- Starting fresh: create a profile with `claude-sync profile create perso`
  and add the shell line yourself (see
  [Shell integration](shell-integration.md)):

  ```sh
  eval "$(claude-sync shell-init zsh)"
  ```

## Upgrade

Install again over the existing copy:

```sh
uv tool install --force --reinstall git+https://github.com/ylepalud/claude-sync
```

or, from an updated clone, `git pull` then `CLAUDE_SYNC_SOURCE=.
./install.sh`. Keep `--reinstall`: the version in `pyproject.toml`
rarely changes, and without it uv reuses the wheel it already built for
that version, so an install from a local clone keeps the old code (the
symptom: commands listed in this documentation are missing from
`claude-sync help`). There are no tagged releases yet: an install from GitHub
takes the default branch.

The shell snippet is generated by the installed version each time a shell
starts, so open shells keep the old one until you run `claude-sync-reload`
or open a new shell. Your configuration, profiles, sources and backups are
not touched by an upgrade.

## Remove the tool

Removing the package does not touch your profiles. If you migrated with
`init`, decide first whether you keep the profiles:

- **Go back to a plain `~/.claude`.** Run `claude-sync uninstall` while the
  tool is still installed: it unloads the LaunchAgent, removes the
  `~/.zshrc` block it added and moves the default profile back to
  `~/.claude` (see [Migration](migration.md)). Then remove the package.
- **Keep the profiles but drop the tool.** Remove the package; the
  `~/.zshrc` block is guarded by `command -v claude-sync`, so the shell
  starts cleanly without it, but `CLAUDE_CONFIG_DIR` is then no longer set
  in your shells. The LaunchAgent keeps setting it to the default profile
  at login until you remove it yourself: `launchctl bootout
  gui/$(id -u)/io.github.ylepalud.claude-sync.env`, delete
  `~/Library/LaunchAgents/io.github.ylepalud.claude-sync.env.plist`, then
  `launchctl unsetenv CLAUDE_CONFIG_DIR`.

Then:

```sh
uv tool uninstall claude-sync
```

What stays until you delete it yourself: `~/.config/claude-sync/` (the
configuration, the profiles, the skill clones in `sources/` and the
backups), and an `eval` line you added to `~/.zshrc` by hand (without the
`command -v` guard of the `init` block, it prints an error at every shell
start once the tool is gone: remove it).
